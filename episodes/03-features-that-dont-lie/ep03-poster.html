Three traps — and what fixed them
Trap
A total hides the trend. "Watched a lot, then stopped" looks like "watched steadily".
→
Split the window
Early vs late sub-windows, plus a weekly slope, built with SQL window functions. Late-window engagement was the strongest signal in the model.
Trap
Using something the model won't have yet. It looks brilliant in training, then fails live.
→
Point-in-time cut-off
One row per billing cycle. Features only from before the cut-off, the label only after the renewal window closes.
Trap
Features built twice — once for training, once for scoring — quietly drift apart.
→
One gold feature table
One table, governed in Unity Catalog at the label's grain — training and scoring read the same thing. Next for me: Feature Engineering in UC.
Most of the work wasn't picking a model. It was deciding what the model is allowed to know, and when.
